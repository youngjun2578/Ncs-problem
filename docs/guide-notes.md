# 가이드 작성 메모

가이드 원고(`content/guides/`)를 다듬을 때 참고할 메모입니다. 빌드 결과물에는 포함되지 않습니다.
글마다 "직접 경험이나 사례를 덧붙이면 좋은 위치"와 "확인이 더 필요한 표현"을 한 단락씩 적었습니다.

공통: 모든 예제의 문제·보기·정답 위치는 엔진이 고정 시드로 만든 것이고, 풀이와 본문 숫자는 빌드 때 코드로 검산됩니다(`scripts/guides/examples.ts`, `claims.ts`). 본문에 숫자를 새로 넣으면 `claims.ts`에도 같은 문장을 추가해야 검산됩니다. 템플릿이나 시드를 바꾸면 예제가 달라지거나 빌드가 멈출 수 있습니다.

## ncs-math-overview (NCS 수리능력, 4개 영역 한눈에 보기)
"공부하는 순서" 바로 뒤에 영준님이 영역별로 실제로 어디서 막혔는지, 어떤 순서로 공부했는지 짧은 경험을 넣으면 허브 글의 설득력이 커집니다. "NCS 직업기초능력의 수리능력은 … 능력을 봅니다"라는 설명은 일반적인 소개로 썼으며, 공식 문서의 정의를 인용한 것이 아니므로 공식 표현과 비교해 보는 것이 좋습니다. 영역 구분(4개)은 이 사이트의 분류임을 본문에 밝혀 두었습니다.

**반영됨** (2026-10-05): "공부하는 순서" 바로 뒤에 운영자 경험(영역을 알게 된 계기, 쉽고 어려웠던 영역, 권하는 공부 순서)과 오답 보기 설계 이야기를 인용 블록으로 넣음. 권하는 공부 순서(도표 영역부터)가 "영역별로 먼저 읽을 가이드"의 순서(기초연산부터)와 다르므로 어느 쪽으로 맞출지 결정 필요.

## speed-round-trip-average (속력·거리·시간)
"자주 하는 실수" 첫 항목 뒤에, 실제로 가운데 값을 골랐던 경험이나 시험장에서 시간에 쫓길 때 어떻게 확인했는지를 덧붙이면 좋습니다. "평균 속력은 두 속력의 가운데 값보다 항상 느린 쪽에 가깝게 나옵니다"는 갈 때와 올 때의 거리가 같을 때만 맞는 설명이라, 그 조건을 앞 문장에 적어 두었습니다. 템플릿에는 같은 방향으로 따라가는 문제가 없어 다루지 않았습니다.

**반영됨** (2026-10-05): "자주 하는 실수" 첫 항목 안에 운영자 경험(처음에 50으로 계산한 일)을 인용 블록으로 넣음. "풀이 순서" 뒤의 기존 설명 단락에 120km로 시간 차이를 보여 주는 설명을 합침(숫자는 claims.ts에서 검산).

## concentration-mix-water-evaporation (농도)
요청 주제는 "섞기와 덜어내기"였지만 템플릿에는 용액 일부를 덜어내는 형태가 없어 "섞기, 물 넣기, 증발"로 바꿨습니다. 덜어내기 문제를 다루려면 템플릿을 먼저 추가해야 합니다. "섞기는 가중 평균이다" 단락 뒤에 표 그리기를 실제로 어떻게 연습했는지 경험을 넣을 만합니다. "희석은 묽게 만든다는 말입니다"는 일상어 설명이므로 그대로 두어도 됩니다.

**반영됨** (2026-10-05): "섞기는 가중 평균이다" 단락 뒤에 운영자 경험(식으로 풀고 소금의 양으로 확인)을 인용 블록으로 넣음. "풀이 순서" 뒤 설명은 기존 표 앞 문장과 합침(처음 소금의 양 → 전체 양 → 나누기 단계는 풀이 순서와 겹쳐 뺌).

## work-rate-one-unit (일의 양)
"칸으로 세는 방법 정리" 뒤에, 분수 방식과 칸 방식 중 어느 쪽이 실제로 더 빨랐는지 영준님의 선호를 한두 문장 넣으면 좋습니다. "칸"이라는 표현은 이해를 돕기 위해 고른 말이며 교재에서 흔히 쓰는 용어(예: 전체 일의 양을 최소공배수로 두기)와 다를 수 있으니, 독자에게 익숙한 표현인지 확인이 필요합니다.

**반영됨** (2026-10-05): "칸으로 세는 방법 정리" 뒤에 운영자 경험(최소공배수로 풀었고 분수 방법은 잘 몰랐음)을 인용 블록으로 넣음. 분수 풀이 설명은 기존 "풀이 순서"와 같은 내용이라 따로 넣지 않고, 경험 문장의 "아래에"를 "이 글의 풀이 순서에"로 고침(분수 풀이가 경험 문단보다 앞에 있음).

## growth-rate-change (증가율과 증가량)
"나중 값에서 처음 값을 거꾸로 구하기" 뒤에 실무나 뉴스에서 증가율을 잘못 읽은 사례를 넣으면 좋습니다(외부 통계 수치는 넣지 않도록 주의). "증감률은 증가율과 감소율을 함께 부르는 말"이라는 설명은 이 사이트에서 쓰는 뜻으로 적은 것입니다. "감소율은 100%를 넘을 수 없습니다"는 값이 0 이상인 자료에서만 맞는 말이라, 음수가 될 수 있는 자료(손익 등)를 다룬다면 문장을 고쳐야 합니다.

**반영됨** (2026-10-05): "나중 값에서 처음 값을 거꾸로 구하기" 뒤에 운영자 경험(증가율과 변화 크기 구분, 변수 두기, 검산)을 인용 블록으로 넣음. 설명 중 x로 두기·감소일 때 (1 − 감소율)·검산 부분을 같은 단락에 합침. 증가량·증가율의 정의는 기존 "용어 정리" 표와 같아 넣지 않음.

## percent-point-share (%와 %p, 비중)
용어 정리 표 아래에, 뉴스나 보고서에서 %와 %p를 섞어 쓴 문장을 본 경험을 덧붙이면 이해가 쉬워집니다(출처가 있는 실제 문장을 옮기지는 말고 상황만 설명). "%p는 보통 작은 수입니다"는 경향을 말한 것이므로 예외가 있다는 점을 염두에 두고 읽어 주세요.

**반영됨** (2026-10-05): 용어 정리 표 아래에 운영자 경험(비중이 더 헷갈렸음)을 인용 블록으로 넣음. "풀이 순서" 뒤에 비율·비중 구분과 기준 값 표시 설명을 넣음(%p와 %의 정의 문장은 용어 정리 표와 같아 뺌).

## mean-median (평균과 중앙값)
"평균이 속이는 경우" 목록 뒤에 실제 경험(예: 점수 평균만 보고 판단했다가 다르게 느낀 경우)을 하나 넣으면 제목과 잘 맞습니다. "보기에는 같은 자료의 평균이나 최빈값이 함께 들어 있는 경우가 많습니다"는 이 사이트의 문제 구성에 대한 설명입니다. 다른 문제집에도 그렇다는 뜻으로 읽히지 않는지 한 번 더 확인해 주세요.

## permutation-combination (순열과 조합)
"순열과 조합을 가르는 질문" 표 뒤에, 순열·조합을 헷갈렸던 실제 문제 상황을 넣으면 좋습니다. 원형으로 앉는 경우의 설명("사람 수로 나누면 됩니다")은 모두 서로 다른 사람이고 회전만 같은 것으로 볼 때의 규칙입니다. 뒤집어서 같은 경우(목걸이 등)는 템플릿에 없어 다루지 않았습니다.

## probability-fraction (확률)
"기약분수로 만드는 법" 뒤에 보기에서 답을 못 찾았던 경험을 넣으면 제목의 "습관"이라는 말과 잘 이어집니다. "보기는 보통 기약분수로 나옵니다"는 이 사이트 문제의 형식을 말한 것입니다. "동시에 2개를 꺼낸다는 되돌려 놓지 않는 경우와 같습니다"는 수학적으로 맞지만, 처음 읽는 사람에게 이유 설명이 더 필요한지 검토해 주세요.

## graph-type-choice (그래프 종류 고르기)
목적별 표 뒤에, 업무 보고서에서 그래프를 잘못 골라 다시 만든 경험 같은 사례를 넣으면 좋습니다. 표의 "띠그래프"는 템플릿 해설에도 원그래프와 함께 나오는 종류이지만, 이 사이트의 보기에는 띠그래프가 나오지 않습니다. 이 점이 독자에게 혼동을 주지 않는지 확인해 주세요. "막대그래프 — 항목끼리의 크기"는 일반적인 기준으로 적었습니다.
