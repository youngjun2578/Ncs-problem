## 점검 4. 기술 준비 상태
- **robots.txt** [코드]: `User-agent: *`, `Allow: /`, `Disallow: /diagnosis/`, `Sitemap: <VITE_SITE_URL>/sitemap.xml`
  - 광고 크롤러(Mediapartners-Google)를 따로 막는 규칙은 없다.
  - 다만 `/diagnosis/`는 모든 크롤러에 막혀 있다. [공식 확인 안 됨] 이 경로에 광고를 넣으면 광고 크롤러가 내용을 읽지 못한다. 점검 5의 제안대로 진단 화면에 광고를 넣지 않으면 문제없다.
- **sitemap.xml** [코드]: `/`, `/method/`, `/guide/`, 가이드 6편, 모두 9개 URL. 주소는 `VITE_SITE_URL`로 만들어진다.
  - 로컬 `.env`는 **placeholder(`https://example.com`)**다. Production 빌드에 Vercel 환경변수 `VITE_SITE_URL=https://ncsmath.com`이 없으면 canonical·sitemap·robots·OG 주소가 모두 example.com이 된다.
  - **Production 값은 확인하지 못함.** 신청 전 실제 사이트의 `/sitemap.xml`과 페이지 소스의 canonical을 꼭 확인해야 한다.
- **보안 헤더·CSP** [코드]: `vercel.json`이 없고, HTML에도 CSP meta가 없다. 광고 스크립트를 막는 설정은 지금 없다. 나중에 CSP를 넣는다면 광고 도메인을 허용해야 한다.
- **apex/www, HTTPS** [추측]: 저장소에 리디렉션 설정이 없다. Vercel 도메인 설정(대시보드)에서 처리되는 부분이라 확인하지 못했다. Vercel은 기본으로 HTTPS 인증서를 발급한다고 알려져 있다.
- **404** [코드]: `404.html`이 없다.
  - Vercel에서는 플랫폼 기본 404가 나올 것으로 보인다([추측]). 사이트 머리말·꼬리말이 있는 404 페이지를 두는 것을 권장한다.
  - 로컬 `vite preview`는 없는 주소에 200(첫 화면)을 돌려줬다. 이는 미리보기 서버의 대체 동작이라 Production과 다를 수 있다.
- **모바일** [코드, 로컬 실행]: `vite preview`로 꺼진 빌드를 띄우고 320px·390px에서 다음을 확인했다. 가로 스크롤이 생기거나 화면 밖으로 넘치는 요소는 없었고, 페이지 오류도 없었다.
  - 10개 페이지
  - 진단 12문항 풀이 화면과 결과 화면
- **번들·이미지** [코드]:
  - 진단 JS 21KB, 가이드 CSS 2.6KB
  - 공통 CSS 240KB: 대부분 Pretendard 동적 서브셋 `@font-face` 선언이고, 글꼴 파일 자체는 필요한 조각만 받는다.
  - 첫 화면에 `<img>`는 없다. OG 이미지 `og.png`는 46KB다.

## 점검 5. 광고 도입 설계안 (코드는 쓰지 않음)
1. **스위치와 ID**
   - `VITE_ADSENSE_ENABLED`(기본 꺼짐)와 `VITE_ADSENSE_CLIENT`(게시자 ID, 환경변수로만 받음)를 둔다.
   - 지금 `VITE_MONETIZATION_ENABLED`처럼 HTML은 `<!--#if adsense-->` 빌드 분기 안에만 스크립트 태그와 광고 자리를 넣는다.
   - 꺼진 빌드의 dist가 이전 커밋과 같은지 `diff -r`로 확인하는 방식이면, 병합해도 Production은 그대로다. 이용권 작업 때와 같은 방법이다.
   - 스위치가 켜졌는데 ID가 비어 있으면 빌드를 멈추는 검사를 둔다(빈 광고 코드 방지).
   - `ads.txt`도 같은 스위치로 만든다. 저장소에 실제 ID를 커밋하지 않는다.
2. **광고를 넣을 페이지(제안)** — 이 기준이 구글 정책에 맞는지는 **[확인 필요]**
   - 넣음: 가이드 글 6편(본문 중간 1곳 + 본문 끝 1곳), 가이드 목록, method 페이지(끝)
   - 넣지 않음:
     - `/diagnosis/` 전체(풀이 중 화면, 결과 화면): 버튼이 많아 잘못 누르기 쉽고, robots로 크롤러도 막혀 있다.
     - 첫 화면: "진단 시작" 버튼 근처, 본문이 적다.
     - 로그인·계정 창, 404
   - 기존 method 문장("광고는 결과 화면 하단에만")과 결과 화면의 `ad-slot`은 이 제안과 반대다. **결정이 필요**하다.
3. **자리 미리 잡기:** 광고 자리마다 `min-height`를 정한 고정 상자(예: 본문 폭 × 280px 안팎. 크기는 [확인 필요])를 빌드 분기 안에 둔다.
   - 광고가 늦게 오거나 비어도 아래 글이 밀리지 않게 한다.
   - 인쇄할 때는 숨긴다(지금 `.ad-slot`처럼 `print.css`에서 처리).
   - 상자 위에 "광고" 표시를 둔다.
4. **이용권과 연결**
   - 지금 이용권 혜택 목록(`src/ui/monetization.ts`의 `PASS_BENEFITS`)에는 "광고 없음"이 **없다.** 넣으려면 혜택 문구와 method 문구를 함께 고쳐야 한다(결정 필요).
   - 방법: 광고 스크립트를 바로 실행하지 않고, 로그인 확인이 끝난 뒤 이용권이 없을 때만 광고를 채운다. 이용권이 있으면 자리 상자도 접는다.
   - 로그인 스위치가 꺼진 빌드에서는 로그인 코드가 없으므로 모든 방문자에게 광고가 나간다. 이용권 확인을 기다리지 않는다.
   - [추측] 확인을 기다리는 동안 광고가 잠깐 보였다가 사라지는 깜박임을 피하려면, 이용권 확인 후 채우는 순서가 낫다.
5. **광고 도입 뒤 개인정보처리방침에 더할 항목**
   - 제3자 공급업체(구글 포함)가 쿠키를 사용해 광고를 게재한다는 사실
   - 광고 쿠키·식별자로 방문 기록을 바탕으로 광고를 보여 줄 수 있다는 점
   - 개인 맞춤 광고를 거부하는 방법(구글 광고 설정 등)
   - 쿠키를 차단·삭제하는 방법
   - "쿠키를 사용하지 않습니다"라는 지금 문장의 수정
   - 이용권 "광고 없음" 혜택이 있다면 그 처리
   - 정확한 필수 문구는 [공식 확인 안 됨]
   - 유럽 등 일부 지역 방문자에 대한 동의 관리(CMP) 요건이 필요한지는 **[확인 필요]**
