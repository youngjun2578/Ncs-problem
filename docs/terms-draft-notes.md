# 약관·환불 안내 초안(/terms/) 메모

`terms/index.html`은 결제를 공개하기 전에 검토하려고 만든 **초안**입니다. 법률 검토를 거치지 않았습니다.
이 문서는 초안의 각 항목이 어디에 근거하는지, 무엇을 채워야 하는지, 무엇을 확인해야 하는지 정리합니다.

## 1. 공개 제어
- 페이지는 결제 스위치와 이용권 스위치가 모두 켜진 빌드에서만 만들어집니다.
  - 조건: `VITE_PAYMENTS_ENABLED`와 `VITE_MONETIZATION_ENABLED`가 모두 정확히 `"true"`
  - 코드: `vite.config.ts`의 `termsPageEnabled`
  - 이유: 결제 스위치는 이용권이 켜졌을 때만 의미가 있습니다(`docs/payments-plan.md` 1절). 그래서 이용권 꺼짐 + 결제 켜짐 빌드에도 약관 페이지는 만들지 않습니다.
- 꼬리말 링크 "이용 약관·환불 안내(초안)"도 같은 빌드에서만 나옵니다.
  - 꺼진 빌드에서는 `src/partials/footer.html`의 `<!--#terms-link:footer-->` 줄이 통째로 지워집니다. 그래서 꺼진 빌드의 HTML은 이전과 같습니다.
- 켜진 빌드에서도 다음과 같습니다.
  - `noindex`이고 canonical이 없습니다.
  - `sitemap.xml`에 넣지 않습니다. `robots.txt`는 바꾸지 않았습니다.
- 페이지 맨 위에 "초안 · 법률 검토 전" 표시가 있습니다.
- Production 검사(`scripts/check-production.ts`)
  - 결제 스위치가 켜졌거나 약관 페이지가 있는 Production 빌드는 빌드에 실패합니다. 실패 조건은 둘입니다.
    - `/terms/`에 `초안`, `[입력 필요]`, `[확인 필요`가 남아 있을 때
    - 다른 페이지 꼬리말에 "(초안)" 링크가 남아 있을 때
  - 시험은 `npm run test:terms`입니다(`test:api`에도 포함). 초안 표시를 일부러 남긴 음성 시험을 포함합니다.
- 공개할 때 할 일
  1. 이 문서의 2·3절을 끝냅니다.
  2. 초안 배너와 "(초안)" 글자, 모든 `[입력 필요]`·`[확인 필요…]`를 지웁니다.
  3. `noindex`, sitemap, canonical을 다시 정합니다.
  4. 개인정보처리방침을 갱신합니다(별도 결정).

## 2. 항목별 근거 (현재 코드·결정된 사실)
| 초안 항목 | 근거 |
|---|---|
| 서비스 내용(12문항 진단, 리포트, 해설, 연습용 문제) | 진단 화면·리포트 코드, 꼬리말 문구(`src/partials/footer.html`), `/about/`, `/method/` |
| 무료 범위: 로그인 없이 1회, 브라우저에만 기록 | `src/ui/monetization.ts` 무료 1회 표시(브라우저 저장소 키 `ncs-free-diagnosis-used`) |
| 무료 결과: 영역별 요약과 1·2번 해설 | `shared/product.ts` `FREE_EXPLANATION_COUNT = 2`, `src/ui/result.ts`의 잠긴 자리 |
| 무료 결과 인쇄는 무료 리포트만 | `src/ui/result.ts` 인쇄 안내 문구 |
| 이용권 1종, 2,900원 | `shared/product.ts` `PASS_PRICE_KRW = 2900`(서버 상수), 결정 사항(10/6) |
| 한 번 결제로 계속 이용, 구독 아님 | `src/ui/monetization.ts` `PASS_BENEFITS` |
| 이용권 범위: 진단 반복, 12문항 해설, 영역별 상세, 인쇄/PDF | `PASS_BENEFITS`, 서버 채점 응답 범위(`gated`) |
| 로그인: 구글(카카오는 `VITE_KAKAO_LOGIN_ENABLED`일 때만 문구가 바뀜), 이메일 가입 없음 | `src/ui/monetization.ts`, 개인정보처리방침의 같은 문장 |
| 저장 항목: 계정 ID, 이용권 상태(구매 여부·구매 시각·결제 주문 번호). 답안·결과·이름·프로필 사진은 저장 안 함 | `supabase/migrations/20261005000000_entitlements.sql`, `20261007000000_payment_orders.sql`, 개인정보처리방침 |
| 결제가 확인된 뒤에만 이용권 적용, 실패·취소면 적용 안 됨 | `server/payments/service.ts` `confirmPayment`, `cancelPendingOrder` |
| 계정 삭제 시 이용권·주문 기록이 함께 지워짐 | `server/accounts.ts` `deleteAccount`(entitlements 삭제), `payment_orders.user_id ... on delete cascade` |
| 환불하면 그 결제로 받은 이용권 회수 | `server/payments/service.ts` `markRefunded` |
| 이미 이용권이 있을 때 결제가 한 번 더 확인되면 이용권 1회, 운영자가 처리 | 결정 사항(10/7: 중복 결제는 표시만 하고 운영자가 처리, 자동 환불 없음), `markPaid`의 `duplicate` |

초안에 넣지 않은 것은 다음과 같습니다.
- 심화 진단 관련 이용 조건: 이용권과의 관계가 정해지지 않았습니다.
- 실제 결제사 이름·결제 수단·영수증: 결제사가 정해지지 않았습니다.
- 법적 기준을 단정하는 문장.

## 3. 영준님이 채울 항목 ([입력 필요])
사업자 등록과 결제사 가입 뒤에 채웁니다.
- 상호
- 대표자
- 사업자등록번호
- 통신판매업 신고번호
- 사업장 주소
- 연락처(전화 등. 지금은 문의 메일만 있음)
- 결제 대행사 이름
- 결제 수단(카드, 간편결제 등)
- 시행일

## 4. 법적·정책 확인이 필요한 항목 ([확인 필요])
아래 내용은 이 초안에서 판단하지 않았습니다. 전자상거래법 등 관련 법령, 결제사 안내, 필요하면 전문가 검토로 확인합니다.
1. 사이트에 표시해야 하는 사업자 정보의 범위와 위치(꼬리말 표시 등).
2. 이용 기간을 따로 정하지 않은 상품의 표시 방법, 서비스 종료 시 이용권 처리.
3. 결제 도입에 맞춘 개인정보처리방침 갱신 내용. 결제 주문 기록, 결제 대행사에 제공하는 항목.
4. 결제 기록 보관 의무(보관 기간). 의무가 있으면 계정 삭제 동작(cascade)을 바꿔야 합니다(`docs/payments-plan.md` 5절).
5. 이용권이 있는 계정을 삭제하기 전에 환불을 안내할지.
6. 서비스 변경·중단 시 알림 방법·기간, 구매한 이용권 처리.
7. 책임의 범위 문구. 소비자에게 불리한 조항이 되지 않는지.
8. 분쟁 처리 절차·관할 문구가 필요한지.
9. 환불 구역(모두 [확인 필요: 전자상거래법 등 근거와 결제사 안내 확인])
   - 청약철회 가능 여부와 디지털 콘텐츠 예외. 이용을 시작한 뒤의 제한과, 제한하려면 구매 전에 알려야 하는 방법.
   - 환불 기한과 방법, 요청 방법과 처리 기간.
   - 결제 오류 시 처리. 중복 결제 처리 기한과 연락 방법, "결제는 됐는데 이용권이 없음" 처리 기한.
10. 구매 화면(결제 직전)에 약관·환불 안내 링크와 동의 표시가 필요한지. 지금 결제 화면(`src/ui/payments.ts`)에는 약관 링크가 없습니다.
